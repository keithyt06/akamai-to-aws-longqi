§13 XFF

API-14PMUSER_CLIENT_IP 变量 ⚠
⚠ header bug

PMUSER_CLIENT_IP：

  • Edge 节点：{{builtin.AK_CLIENT_REAL_IP}}
  • Parent 节点：从请求头  x-authentic-ip 提取 ⚠
⚠ 生产注意 header 名前导空格 bug：请求头名为 " x-authentic-ip"（注意 header 名前有一个空格）。 HTTP 规范不允许 header name 前导空白，极可能是 bug —— 这里取值会失败； PMUSER_CLIENT_IP 在 Parent 层永远取不到值。迁移到 CloudFront 时顺手修掉。

§15 值得留意 / 风险点

API-16顶层 + Sureroute&Caching 双重 NO_STORE
强意图

强意图——api.beautyforever.com 是纯动态域名，任何缓存必须由源站 Cache-Control 显式开启，否则全部回源。

API-17cacheId 含 cookie（customer_group / currency）
迁移注意

源站如果返回可缓存响应，会按 customer_group + currency 两个 cookie 分版本。 迁移到 CloudFront 需要额外用 CloudFront Functions 规范化这两个 cookie 进缓存键。

API-18XFF header 名前导空格 bug
⚠ 生产注意
⚠ 生产注意 XFF header " x-authentic-ip" 带前导空格 —— 几乎必然是 bug， PMUSER_CLIENT_IP 在 Parent 层永远取不到值。迁移时务必修掉。
API-19breakConnection: enabled=true ⚠
⚠ 生产注意
⚠ 生产注意 breakConnection: enabled=true —— 生产上开着故障注入， 确认是否有意。若为演练残留，迁移时应关闭。
API-20cacheKeyQueryParams IGNORE 列表
迁移注意

枚举了 20+ 个广告追踪参数 —— 迁移时必须搬过来， 否则缓存命中率会暴跌。

API-21与 www/m 的 query 策略差异
策略对比

广告/追踪参数白名单与 www/m 的 INCLUDE_ALL_QUERY_PARAMS 策略不同， 说明 api 路径对 query string 更敏感、要主动屏蔽广告追踪参数污染缓存键。
