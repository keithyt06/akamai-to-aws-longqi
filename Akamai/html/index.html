快速验证（本地实活）

这些命令在本环境可以直接跑，用来快速确认采集到的活体配置与当前行为一致。

LIVE-01 三个域名的边缘响应头
smoke 
curl -sI 'https://www.beautyforever.com/'   | grep -Ei 'x-cache|cache-control|server|edge'
curl -sI 'https://m.beautyforever.com/'     | grep -Ei 'x-cache|cache-control|server|edge'
curl -sI 'https://api.beautyforever.com/'   | grep -Ei 'x-cache|cache-control|server|edge'
预期：www/m 命中 Page Caching 的路径返回 X-Cache: TCP_HIT_ 或 TCP_MISS_ + Cache-Control: max-age=21600；api 基本都是 NO_STORE/X-Cache: TCP_MISS_。
LIVE-02 ?akaCache=nce 绕过缓存
backdoor 
curl -sI 'https://www.beautyforever.com/?akaCache=nce' | grep -Ei 'cache'
预期：一定是 MISS/NO_STORE（Akamai 专属约定）。迁移到 CloudFront 时需保留等价 backdoor。
LIVE-03 PC ↔ Mobile 302 互跳
redirect 
# iPhone UA 访问 www，应 302 → m.*
curl -sI -H 'User-Agent: Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15' \
  'https://www.beautyforever.com/' | grep -Ei '^HTTP|location'

# Desktop UA 访问 m，应 302 → www.*
curl -sI -H 'User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 14_0) AppleWebKit/605.1.15' \
  'https://m.beautyforever.com/' | grep -Ei '^HTTP|location'

# 白名单 UA 不跳转
curl -sI -H 'User-Agent: LqPassWaf/851.3' 'https://www.beautyforever.com/' | grep -Ei '^HTTP'
预期：前两条 HTTP/2 302 + Location: https://...；最后 LqPassWaf UA 返回 200（不跳转）。
LIVE-04 Apple Pay 路径白名单
allowlist 
# Desktop UA 访问 m 的 Apple Pay 验证文件，应 200 而不是 302
curl -sI -H 'User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 14_0)' \
  'https://m.beautyforever.com/.well-known/apple-developer-merchantid-domain-association.txt' \
  | grep -Ei '^HTTP'
预期：HTTP/2 200。若返回 302 说明规则出问题，Apple Pay 域名注册会失败。
