§5 跳转 & 分流规则

M-5Desktop → PC（m → www）302 跳转
核心规则
  • HTTP → HTTPS 301
  • Desktop UA 访问 m → 302 回 www.beautyforever.com（强制 PC 用户到 PC 站）
  • Mobile UA 访问 www → 302 到 m（反向）

Desktop→PC（m → www）跳转白名单（满足任一则不跳）

#条件说明
1 LqPassWaf UA 白名单
UA ∈ ["LqPassWaf/851.3", "LqPassWaf/851.3 (it; Categraf)"]		 内部 WAF / 健康检查 / Categraf 采集
2 Apple Pay 路径白名单
path = /.well-known/apple-developer-merchantid-domain-association.txt		 Apple Pay 域名注册校验（必须保留 m 域名 200 响应，不可重定向）
3 js/css 扩展名白名单
ext ∈ ["js", "css"]		 静态资源不参与 UA 判定
4 deviceCharacteristic[IS_MOBILE] 判定仍为 true 时不触发 继续停留在 m
⚠ 苹果支付域验证 Apple Pay 路径白名单必须保留
  • 路径：/.well-known/apple-developer-merchantid-domain-association.txt
  • 触发场景：Apple Pay 商户 merchantid 域名注册校验时，Apple 从 m.beautyforever.com 拉取该文件
  • 要求：必须 HTTP 200 响应（保留文件内容），不可 302 跳转到 www
  • 影响：若误被 Desktop→PC 规则 302，Apple Pay 注册/续期将失败，m 站支付链路中断
  • 迁移到 CloudFront 时，等价规则需放在 Viewer Request Function 最前面（UA 判断之前）
